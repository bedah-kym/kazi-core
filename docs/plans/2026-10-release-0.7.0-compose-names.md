# Plan: 0.7.0 release — lowercase names in docker-compose.yml
Status: approved by Bedan on 2026-10-04 ("Apply"); applied on `release/v0.7.0`.

## Goal
`docker compose up --build` works on a fresh clone of the 0.7.0 tag.

## Non-goals
Any other change to the compose stack. `docker-compose.oci.yml` and `docker-compose.temporal.yml` are untouched (no uppercase names in either).

## Touches
- Paths: `docker-compose.yml` (8 lines).
- Protected paths? yes: `docker-compose*.yml`.
- Contracts, migrations, approvals, payments, secrets? none.

## Risk class of any new action
None. Configuration only.

## Approach
The Mathia → Kazi rename (fa2938c) wrote the image name as `KAZI-web:latest` on four services. Docker rejects a repository name that is not lowercase, so the build cannot tag the image. The same commit set the database defaults to `KAZI_user` / `KAZI_password` / `KAZI_db`; they work, but they differ from `docker-compose.oci.yml` (`kazi_*`) and mixed-case role names are easy to get wrong in `psql`.

Change: `KAZI-web` → `kazi-web`, `KAZI_user` → `kazi_user`, `KAZI_password` → `kazi_password`, `KAZI_db` → `kazi_db`.

## Verification (executable)
- Done on Docker Engine 29.8 in a throwaway Codespace on the release branch, with this change applied: `docker image tag alpine:3 KAZI-web:latest` fails with "repository name must be lowercase"; `docker compose up --build -d db redis web` builds `kazi-web:latest`; the web container stays up, `migrate` and `seed_kazi` run from the entrypoint, and `GET /` returns 200.
- Failure paths covered: none new.
- Injection corpus cases added: none.

## Rollback
`git apply -R` the patch.

## Open questions for the human
- Anyone who initialised a volume from `main` since the rename has a role named `KAZI_user`. The changelog tells upgraders to pin `POSTGRES_*` and `DATABASE_URL` on an existing volume. Is that enough, or do you want the database defaults left as they are and only the image name fixed?
